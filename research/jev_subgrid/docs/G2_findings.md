# G2 해석 — Jev는 좋은 국소 후보를 고르는가

자동 보고서: [`results/g2/report.md`](../results/g2/report.md). 이 문서는 그 숫자를 해석하고, 사전 기준 밖에서 한
탐색 분석을 **탐색 분석이라고 표시해서** 덧붙인다. 판정은 사전 기준 하나로만 내린다.

## 1. 판정

**G2 미통과.** 사전 고정 기준은 "실제 후보 집합에서 Jev L2가 무작위·R1·R2 각각보다 핵심 구조 성공률이 높고,
paired bootstrap 95% CI가 0을 포함하지 않으며, 두 선택지 순서 모두에서 성립"이다.

| 비교 (실제 집합, 240문제) | 차이 | 95% CI | 결과 |
|---|---:|---|---|
| L2 − 무작위 | +41.3 / +40.0%p | 두 순서 모두 0 초과 | ✅ |
| L2 − R1(교차 최소) | −4.2 / −5.4%p | 0 포함 | ❌ |
| L2 − R2(가장 단순한 물체) | −10.0 / −11.2%p | 0 미만 | ❌ |

Jev L2는 무작위보다 확실히 낫다(29.6% → 70.2%). 하지만 코드 한 줄짜리 규칙 R2(80.8%)보다 낫지 않다.
Jev 비용은 요청 600회에 입력 216만 토큰, **$0.09**였다.

## 2. 실패의 원인 두 가지

### 2.1 풀 수 없는 형상 3개 (30문제) — 표현 쪽 문제, 선택자와 무관

`helmet_100`, `holed_plate_100`, `holed_plate_103`에서는 **정답 A 자체**가 n=64에서 틀린 위상으로 복원된다.

| 형상 | 정답 A 복원 결과 | 해당하는 G1 실패 유형 (위상 수치로 추정, 부위는 미확인) |
|---|---|---|
| helmet_100 | 성분 2, genus [0,1] | 파편화(조각 분리) + 가짜 터널 |
| holed_plate_100 | 성분 2, genus [0,2] | 파편화(조각 분리) |
| holed_plate_103 | 성분 1, genus 7 | 구멍 수 과다(가짜 터널 또는 틈 병합) |

그래서 이 30문제에서는 모든 선택자가 0%이고, 상한(`oracle_best`)도 0%다. 성공률은 모든 선택자에서
같은 폭만큼 깎이므로 판정 순위는 바뀌지 않는다. 대신 **G1 결론에 단서를 달아야 한다.**

- G1의 "n=64에서 100%"는 G1 분할의 변형 48개(시드 0–7) 기준이다.
- 시드가 겹치지 않는 G2 변형 24개(시드 100–103)로 보면 정답 A의 핵심 구조 보존률은 **21/24 = 87.5%**다.
  G1 목표치 90%를 밑돈다.
- 표본이 작아 추정 폭이 넓지만, "n=64면 항상 충분하다"는 **과대 해석이다.** 격자 칸 크기에 가까운 얇은 벽과
  좁은 틈은 n=64에서도 깨질 수 있다. G1_findings의 실패 유형(가짜 터널, 파편화, 병합)이 여기서 다시 나왔다.

### 2.2 thin_shell의 단어 함정 — 설명문 설계 결함 (내 책임)

thin_shell 계열에서 Jev L2는 20%, R2는 75%다. 형상별로 보면 다음과 같다.

| 형상 (조건문) | L0 | L1 | **L2** | R2 |
|---|---:|---:|---:|---:|
| thin_shell_102 ("…with one round **opening** into the empty inside") | 60% | 80% | **0%** | 100% |
| thin_shell_103 ("…two round **openings**…") | 90% | 60% | **10%** | 100% |

- 구멍 뚫린 속빈 공은 위상적으로 **구멍이 없는** 곡면이다(genus 0). 입구는 관통 구멍이 아니다.
- 그런데 L2 효과 요약은 "the whole object … with N **through-hole(s)**"라고 쓴다. 조건문의 "opening"과
  효과 요약의 "through-hole"이 같은 뜻처럼 읽힌다.
- Jev L2는 거의 매번 holes=1이나 holes=2인 후보를 골랐다. 입구 개수를 구멍 개수에 맞춘 것이다.
- L0처럼 효과 요약이 없는 수준에서는 이 함정이 생기지 않는다.

이건 Jev의 공간 추론 실패라기보다 **내가 쓴 설명문의 어휘 충돌**이다. 사람도 똑같이 헷갈릴 수 있다.
사후에 고친 문구로 다시 재면 사전 기준을 무력화하게 되므로 판정에는 쓰지 않는다. 대신 다음 실험의 설명문 규칙으로 남긴다.
효과 요약은 위상 용어("through-hole")가 아니라 관찰 가능한 사실로 써야 한다.
예: "a string can pass through the object and come back around".

## 3. 탐색 분석 (사전 기준 밖, 판정에 사용하지 않음)

| 부분집합 | n | 무작위 | R1 | R2 | L0 | L1 | **L2** | 상한 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 전체 | 240 | 29.6% | 75.0% | 80.8% | 63.7% | 49.4% | **70.2%** | 87.1% |
| 풀 수 있는 형상만 | 210 | 33.8% | 85.7% | 92.4% | 72.9% | 56.2% | **81.0%** | 99.5% |
| 〃 − thin_shell | 170 | 33.1% | 88.2% | 96.5% | 74.7% | 57.6% | **94.7%** | 99.4% |

순서 p0 기준이다. 마지막 행에서 L2−R1 = +6.5%p [+0.6, +12.4], L2−R2 = −1.8%p [−5.9, +2.4]다.

- 두 원인을 걷어내면 Jev L2는 R1보다 낫고 R2와 비긴다. 다만 **R2를 넘지는 못한다.**
- R2("조각·구멍·기포 수가 조건문과 가장 가까운 후보")는 효과 요약만 있으면 코드로 계산된다.
  그러니 L2 설명문이 주어진 상태에서 Jev가 보태는 정보는 R2가 이미 가진 정보를 넘지 않는다.
- 이 해석에 따르면 L2에서 Jev는 조건문에서 개수를 읽어 효과 요약과 맞추는 일을 한다. 이 일은 규칙으로 더
  정확하게 할 수 있다.

### 3.1 L0 > L1 이상 현상

주변 구조 설명(L1)을 더하면 성공률이 떨어진다(63.7% → 49.4%).

- 두 순서의 선택 일치율은 L0 43%, L1 69%다. L1은 **더 일관되게 틀린다.**
- 이웃 블록의 교차 수를 긴 숫자 목록으로 주면 Jev가 그중 표면적인 특징(예: 짧은 후보나 특정 숫자 패턴)에
  끌린다고 보는 게 가장 그럴듯한 설명이다.
- Jev 문서가 경고한 "숫자·공간·세기에 약함"과 일치한다. 숫자를 늘리면 도움이 되지 않고 방해가 된다.

### 3.2 보정(calibration)

L2가 고른 후보의 확률이 높을수록 실제 성공률도 오른다(0.0–0.4: 53% → 0.4–0.6: 77% → 0.6–0.8: 78%).
방향은 맞지만 평균 confidence가 0.38로 낮다. 0.95 이상은 한 번도 없었다.
Jev의 확률은 "이 후보가 맞을 가능성"이 아니라 거친 순위 신호로만 쓸 수 있다.

## 4. 이것이 다음 단계에 뜻하는 것

1. **숫자 설명만으로 Jev에게 공간 판단을 맡기는 설계는 한계에 닿았다.**
   - 숫자만 주면(L0) 무작위보다는 낫지만 규칙보다 못하다.
   - 숫자를 더 주면(L1) 나빠진다.
   - 요약을 주면(L2) 결국 규칙이 하는 일을 한다.
   - G4 파일럿(프롬프트 → 격자점 점유)이 5/5 실패한 것도 같은 결론을 가리킨다.
2. **시각 피드백이 빠진 것이 핵심 결손이다.** 사용자가 새로 제안한 방법(점 격자 성장 + 렌더링 이미지 피드백 +
   Gemma 4 기반 멀티모달 모델)은 정확히 이 결손을 겨냥한다. 그 실험에서는 G2의 교훈을 그대로 가져간다.
   - 설명문에 위상 용어를 쓰지 않는다(§2.2).
   - 숫자 목록 대신 이미지를 준다(§3.1).
   - 규칙 기준선(R2 계열)을 반드시 같이 잰다. 규칙을 못 이기면 모델을 쓸 이유가 없다.
3. **표현의 여유를 늘려야 한다.** 격자 칸에 가까운 얇은 구조는 n=64에서도 깨진다(§2.1). 생성 실험의 목표
   형상은 얇은 구조를 격자 칸 2개 이상으로 잡거나, 해상도를 높인 설정도 함께 보고한다.

## 5. 재현

```bash
python -m jevsg.experiments.g2 build  --cache <G1 참조 캐시>   # 240문제, 모델 호출 없음
JEV_API_KEY=... python -m jevsg.experiments.g2 choose --jev-cache <캐시>
python -m jevsg.experiments.g2 report
```

문제 파일(`results/g2/problems/*.json`)과 선택 결과(`results/g2/choices.jsonl`)를 저장소에 함께 둔다.
모든 Jev 요청과 응답은 내용 해시로 캐시되며, 모델 버전은 `jev-1.13.0`으로 고정했다.
