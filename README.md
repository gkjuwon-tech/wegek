# WEGEK — AI 3D Render Studio (v2)

A full pivot. The old approach assembled primitives in a Three.js scrollytelling
template and looked cheap. v2 treats **Blender as the renderer** and the AI as a
**technical art director** that sets a scene up properly, then bakes the *exact*
result into a deployable site.

## The agent workflow (what the backend orchestrates)

1. **Plan** — an LLM designs a 3-act experience: **three distinct scenes** that
   hand off to one another on scroll (Active-Theory grammar: a scene holds, you
   scroll, it transitions naturally into the next). Each scene declares its meshes,
   keyframed animation, camera move, lighting (incl. rim lights), HDRI and palette.
2. **Outsource meshes → Tripo** — every mesh the plan needs is generated by Tripo
   (reference image → 3D GLB). No procedural stand-ins.
3. **Build in Blender** — a generated `bpy` program opens Blender, imports the GLBs,
   keyframes their rotation/animation, sets the cameras, rigs 3-point + rim lighting,
   loads an HDRI, and lays out the **three transitioning scenes**.
4. **Render & export** — Blender path-traces each scene/transition (Cycles) and
   **exports the exact scene data** — world-space coordinates, keyframes, camera
   paths, lights — not previz guesses.
5. **Bake to code** — the exported, real Blender coordinates are baked into the site
   spec so the frontend reproduces precisely what was art-directed (no hand-placed
   approximations).

> Backend first. The frontend that consumes the baked spec / rendered frames comes later.

## Why Blender
Real PBR materials, HDRI image-based lighting, rim lights, path tracing and a proper
camera rig — quality the previz Three.js path could never reach. The AI authors the
`bpy` setup; Blender is the ground truth; code only ever mirrors a finished scene.

## Layout
```
backend/app/
  config.py            settings (Tripo/LLM keys, paths)
  schemas.py           Experience / Scene / SceneObject / Camera / Light
  clients/             tripo.py (mesh outsourcing), llm.py (planner)
  pipeline/
    plan.py            LLM designs the 3-scene experience
    meshes.py          outsource each mesh to Tripo
    blender_build.py   emit the bpy program + (later) run Blender
    bake.py            Blender export -> baked site spec (real coords)
    orchestrator.py    run the job end to end
  blender/build_scene.py   the bpy program template run inside Blender
  main.py              FastAPI
```
